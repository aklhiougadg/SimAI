## 一条完整的网络仿真链

模型与并行参数 → AICB mocked model → workload → Workload/Layer 调度 → SimCCL 选择算法、协议、channel 并生成有依赖的点到点 Flow → NcclFlowModel → sim_send/SendFlow → RdmaClient/RdmaDriver/RdmaHw 创建 QP → 分包与网卡调度 → 链路序列化和传播 → 交换机转发、排队、ECN/PFC → 接收端 ACK/NACK → 源端确认、速率更新、QP 完成 → 上层通信与训练流程继续。

## 当前 GPT-13B 输入与拓扑

`experiments/gpt13b_128g/workload_gpt13b.txt`：128 GPU，TP=2，PP=1，EP=1，DP=64，GA=2，40 层，336 条记录，声明数与实际数一致。参数清单给出 MBS=1、GBS=128、序列长度 2048、hidden=5120、FFN=20480，启用 sequence parallel，关闭 AIOB。

此 workload 每个常规计算字段主要为 1，是计算占位，不是 H100 实测 kernel 时间。其网络结果描述“该注入时序下”的行为，不能直接视为真实训练的吞吐量、计算通信重叠比例或瓶颈占比。

拓扑文件头为 `216 8 16 72 768 H100`：

- GPU 0–127，共 16 台服务器，每台 8 GPU。
- NVSwitch 128–143，共 16 个。
- ASW 144–151，共 8 个；PSW 152–215，共 64 个。
- GPU–NVSwitch 128 条链路：2880 Gbps、25 ns。
- GPU–ASW 128 条链路和 ASW–PSW 512 条链路：400 Gbps、500 ns。
- 共 768 条双向物理连接；分析端口流量时需要分别统计两个方向。

模板为 rail-optimized Spectrum-X。同服务器可走 NVSwitch；不同服务器的同 rail GPU 可经一个 ASW；不同 rail 的跨服务器通信可能经 ASW–PSW–ASW。实际路径还由点到点端点、路由候选、QP 端口和 ECMP 哈希决定。拓扑名本身不表示已经实现商用 Spectrum-X 的全部自适应路由行为。

TP 组在当前组构造中按连续 rank 划分，例如 {0,1}；DP=64 时的两个 DP 组分别为偶数和奇数 rank。这会决定通信是服务器内还是跨服务器，以及哪些 rail 承受流量。

## 路由、负载均衡与拥塞控制

`CalculateRoute` 反向遍历拓扑，建立按跳数的最短路径候选，同跳数下对 NVSwitch 有特殊偏好；`SetRoutingEntries` 把候选下一跳转换成本地出口。

`SwitchNode::GetOutDev` 使用源/目的 IP 和源/目的端口组成的 12 字节键进行 ECMP 哈希，取模选择出口。协议决定读取哪类端口字段，但协议号本身不在这个键中。稳定路由表下，同一 QP 的数据包走同一哈希选择；这里没有按实时队列长度选最空闲路径。端侧也按 QP 哈希选择候选 NIC。网卡对可发 QP 的轮询调度是另一个层次的问题，不等于网络自适应路由。

已有配置选择 `CC_MODE 1`：Mellanox 风格 DCQCN。

1. 普通交换机在出队时根据出口队列占用判断 ECN 标记。
2. 接收端在 ACK/NACK 中设置 CNP 标志；当前关键降速路径是 `ReceiveAck → cnp_received_mlx`，不能只按独立 CNP 报文的一般描述解释。
3. 发送端更新 alpha、目标速率与当前速率，按定时器降速、快速恢复及加性增速。
4. QP 速率通过发送节奏约束影响下一次可发送时间；窗口、PFC 和物理链路忙碌也分别约束发送。

PFC 是逐跳、按优先级暂停与恢复，区别于 DCQCN 的端到端速率调节。普通交换机具有 ECN 标记与 PFC 触发/恢复逻辑；NVSwitch 转发实现虽有 MMU 入队检查和计数，却没有同样的 ECN 标记与 PFC 触发/恢复调用，不能把两者等同。当前 NS-3 NVSwitch 路径不应被描述为真实 NVLink 协议的完整硬件实现。

DCQCN 的 `RateOnFirstCnp` 默认值为 1.0，首次反馈初始化 alpha 和定时器，并不立即按小于 1 的系数降低速率；之后由降速定时器执行更新。`RP_TIMER` 控制增速恢复定时器，alpha 更新周期是另一个参数 `ALPHA_RESUME_INTERVAL`。

400 Gbps 配置的 ECN 阈值为 KMIN=800、KMAX=3200，经 `ConfigEcn` 乘 1000，实际是 800,000 B 和 3,200,000 B，PMAX=0.2。BUFFER_SIZE=32 经代码转换为 32 MiB。其他支持的分支包括 HPCC=3、TIMELY=7、DCTCP=8、HPCC-PINT=10；配置中存在这些算法的参数不表示当前 DCQCN 会使用它们。

## workload 参数不能只看名字

- **AICB 生成端**：`DP = world_size / (TP × PP)`；`GA = global_batch / (DP × micro_batch)`；EP 在这里细分 DP 维度，DP_EP=DP/EP。
- 代码会检查 world_size 的部分整除关系，但 global_batch 整除断言已注释，GA 使用整除。生成前应核对正数、整除、heads/hidden/TP、层数/PP、experts/EP、DP/EP 等约束，不能依赖程序全部拦截。
- **Simulation 运行端存在不同限制**：`Sys::mock_nccl_grobal_group_init` 和 `mock_nccl_comms_init` 把 PP_size 固定为 1。不能把生成端接受 PP 参数等同于运行端完整支持 PP；当前 PP=1 实验不触发这一差异。
- PP>1 会把总层数整除 PP；当前输出的 `vpp` 来自划分后的 num_layers，不能直接解释为标准意义的虚拟流水线阶段数。
- 基础 TP 数据量在普通生成分支写成 `2 × MBS × seq_length × hidden_size`；当前 GPT 配置得到 20,971,520 B。字节系数存在硬编码，改变 `dtype` 不能默认所有通信字节数自动重算。
- 普通生成分支开头 grad_norm 的 AllGather 为 `2 × total_params`，ReduceScatter 为 `4 × total_params`。total_params 来自 mocked model 的实际参数对象，不应直接用模型名中的“13B”替代。
- 生成器的普通分支没有通过 `epoch_num` 循环展开多轮，也未按 `use-distributed-optimizer` 开关分支生成这一对操作；传入参数不等于该路径使用了参数。
- `max_position_embeddings` 在当前 Megatron mocked embedding 中没有决定位置嵌入形状，该对象实际使用 seq_len；word embedding 形状还包含 `4 × padded_vocab/TP`。这影响精确参数量，需按源码解释。
- `NONE` 操作可能伴随非零 size，统计时必须先看通信类型。336 条记录中也有 MoE 名称但零字节的记录，不能因此认定是 MoE workload。
- fwd/ig 的普通集合通信在解析器中默认归 TP，wg 默认归 DP；不能只凭 `grad_norm` 名称把其前向 AllGather 标成 DP。
- AIOB 生成分支可以读取已有计算 profile，或进行实测；是否需要 GPU 取决于是否要重新采样。比较不同模型时，应保留完整生成命令和 profile 来源。

论文表 3 给出 GPT-13B 的 hidden=5120、40 层、sequence=2048、FFN=20480、TP=2、PP=1。模型结构、并行策略、批量策略、GPU/网络配置应分别标明来源。保持 GA=2 并改变 TP/DP 会同时改变全局 batch；这类比较不是等 token 数比较，后续应由实验问题决定固定什么并如何归一化。

## 指标与现有产物

| 数据 | 能回答的问题 | 边界 |
|---|---|---|
| workload | 逻辑算子、通信类型、张量规模 | 不是全网链路字节数 |
| detailed_flows CSV | 集合通信分解、端点、channel、依赖 | 模型导出，不自动等于运行时事件日志 |
| fct.txt | 已完成 QP 的端点、负载量、开始时间、FCT | 不含实际逐跳路径；不能独立证明整个训练完成 |
| EndToEnd CSV | 暴露通信、计算、训练完成时间等 | 当前 checkout 未保存这些文件 |
| bw.txt | 采样窗口内端口发送速率（Gbps） | 需要端口映射和统计范围，区别于 payload goodput |
| qlen.txt | 交换机端口/优先级队列占用（B） | 采样且仅在端口总量改变时写记录，可能漏掉短暂峰值 |
| rate.txt/cnp.txt | 活动 QP 速率、累计反馈计数 | 采样可能漏掉寿命很短的 QP；还存在下述格式问题 |
| pfc.txt | 暂停/恢复事件 | 空文件不表示从未排队或发生 ECN |
| trace.tr | 启用节点的逐包事件 | 现有文件实际都仅有文件头 |

`fct.txt` 共 8 列：sip、dip、sport、dport、size(B)、start、FCT、standalone_fct。时间在当前默认 NS-3 时钟下为 ns，CSV 时间经 FREQ 换算为 µs。start 在 QP 创建时记录，因此 FCT 不包含此前 SendFlow 的应用启动延迟。standalone_fct 是按路径 RTT、瓶颈速率和包头估算的基准，不是重新运行的严格无竞争实测；轻微小于 1 的 FCT/base 比值不能直接认定数据错误。

链路利用率应按方向计算：采样窗口实际发送 bit / (该方向链路 bit/s × 窗口秒数)。端到端 payload、带包头的端口发送量、ACK/PFC 流量、沿多跳累加的 byte-hop、集合通信 algbw/busbw 是不同口径。FCT 之间可重叠，不能直接求和当作训练耗时。`Layer::compute_busbw` 中 GBps 宏按 1024³ 换算，因此 algbw/busbw 实际口径是 GiB/s；它们不是链路利用率。Simulation 汇总 `total_exposed` 最终被赋为 `Now/FREQ - total_compute`，是剩余时间，不能全部解释为纯网络排队或传输时间。

## 已核实的差异与后续实验注意点

1. **发送延迟说明与实现冲突。** `entry.h` 将环境变量或查表值乘 1000，再传 `Time(int)`。本地 NS-3 的 `SetDefaultNsResolution` 设置 NS，当前主路径没有切成 PS；数字 Time 构造按当前 resolution。由此当前源码下 `AS_SEND_LAT=3` 对应 3000 ns，即 3 µs。英文 send-lat 文档和旁边的“ns→ps”注释不能直接采信。e01 首个开始时间 559010 ns 与 556000 ns 计算加约 3000 ns 启动延迟相符。旧二进制仍需单独确认，本文没有执行新的验证实验。
2. **E0 记录与数据不符。** E0 文本写总时间 1433.593 µs，但其 FCT 最晚完成时刻约 181.404 ms；e01 的最晚完成时刻约 1433.583 µs。两个 FCT 的记录数、总 payload 和平均 FCT 一样，启动/调度时间不同。具体历史命令不能从目录名唯一还原。
3. **监控已修复部分旧问题。** 提交 291b60c 加入 ENABLE_MONITOR（默认 false）和四类监控 MON_END 判断。旧笔记说 MON_END 不起作用已经过时。GPT-H100 配置未写 ENABLE_MONITOR，因此当前代码重跑默认不采样；A100 配置写了 1。MON_START/END 与采样间隔的配置单位为 µs，输出 time 字段为默认 ns。
4. **监控数值输出仍有问题。** `PrintQPRate` 用 `%u` 输出 `GetBitRate()`，但其类型是 uint64_t；同处 size 也是 64 位。存在可变参数格式不匹配，高速率可能显示错误。正式用 rate.txt 判断 DCQCN 效果前应处理并验证。此次未修改源码。
5. **现有逐包 trace 没有事件。** 按 SimSetting 格式核算，所有 trace.tr 的大小都恰好为 `8 + 11 × 端口记录数`，无剩余事件字节。这与 trace1.txt 选择 0 个节点一致，不能从这些文件还原已运行的实际路径或队列曲线。
6. **GLOBAL_T 被强制为 1。** 尽管配置是 0，ReadConf 随即设为 1，QP 实际使用 maxRtt/maxBdp。SIMULATOR_STOP_TIME 被读取但没有在当前主路径用于预先预约停止。
7. **监控覆盖与统计窗口有边界。** NVSwitch 的带宽输出读取转发计数，而 NVLS 端点发送更新的是 RdmaHw 计数；当前采样分派没有完整覆盖这部分流量。rate/cnp 只遍历 GPU 类型节点。带宽首次采样使用自时间 0 起累计量除以配置 interval，MON_START 不等于 interval 时不能视为普通固定窗口；末尾不足一个窗口没有自动补采样。PFC 文件是接收侧事件，不是发送侧事件。
8. **小消息与完成回调存在硬编码。** 当前 Transformer fwd-in-bckwd 调度分支把正数且小于 4096 B 的前向通信放大到 4096 B。QbbNetDevice 的两个发送入口以 `60 < packet_size < 9000` 判断发送完成回调，改变 MTU 前必须验证这个假设，不应直接进行大规模 MTU 扫描。此处是静态风险，尚未通过新实验重现故障。
9. **参数存在局部生效或不生效的情形。** ACK_HIGH_PRIO 只在初始化中设置 RdmaEgressQueue 的 ACK 队列索引，没有同步配置交换机的 AckHighPrio 属性；DynamicThreshold 属性未见运行时使用；NIC_TOTAL_PAUSE_TIME 对应成员未见运行时使用。SimCCL 的 SIMAI_FORCE_ALGO 仅出现在注释，不能当成有效开关。
10. **关键结果没有同步。** `.gitignore` 排除了 `ncclFlowModel_*.csv`、日志、results 和编译产物；当前目录也没有 bw/qlen/rate/cnp 输出。保留 FCT 不等于保留完整复现资料。

后续接到具体任务时，应按其目标选择模型与固定条件，并先确认所需观测能实际生成、单位和计数类型正确，再解释链路瓶颈。当前只是完成研究准备与数据核对，未擅自开始参数扫描或更换实验路线。
